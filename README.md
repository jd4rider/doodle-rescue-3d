# Doodle Rescue 3D

A 3D physics drawing adventure for [Little Joy Arcade](https://littlejoyarcade.site).
Draw real beams, shelters, bridges and ramps, then watch the physics decide
whether Biscuit the puppy is safe.

Play: <https://jd4rider.github.io/doodle-rescue-3d/>

Built with **Godot 4.7.2** (Compatibility renderer, single-threaded Web export).
Every visual and every sound is generated by the project: procedural 3D props in
GDScript, WAVs synthesised by `Tools/audio.py`.

---

## What is here

| Path | What it is |
|---|---|
| `Scripts/Draw/` | Screen-to-plane drawing, smoothing, simplification, procedural beam meshes and collision |
| `Scripts/World/` | Level runtime, Biscuit, bees, hazards, diorama props |
| `Scripts/Screens/` | Title, journey map, level grid, gameplay, settings, pen tin, trophies |
| `Scripts/Core/` | Save schema, audio, Little Joy Arcade bridge, catalogue loader, router |
| `Data/levels.json` | The 20 committed levels, their solutions and star budgets |
| `Tests/HeadlessTests.gd` | Data validation and a full physics replay of every stored solution |
| `Tools/audio.py` | Synthesises all music and effects |
| `Tools/patch_web.py` | Adds the account layer and full-bleed framing to the web export |
| `Tools/smoke.mjs` | Browser test: real drag on the canvas, real win, screenshots |
| `docs/QA_REPORT.md` | What was actually verified, and what was not |

## Run it

```bash
godot --path .                                   # editor / game
godot --headless --path . Scenes/Tests.tscn      # all levels, in real time
godot --headless --path . Scenes/Tests.tscn -- 1 # one level
```

The full suite replays every stored solution through the shipping physics, so it
takes a few minutes (the bridge levels alone spend several seconds walking).
Pass level ids after `--` while iterating.

## Build and deploy

```bash
godot --headless --path . --import
godot --headless --path . Scenes/Tests.tscn
godot --headless --path . --export-release "Web" web/play/index.html
python3 Tools/patch_web.py
```

The GitHub workflow runs exactly those steps and publishes `web/play` to the
`gh-pages` branch. Pages serves that branch at the URL above. Local check:

```bash
python3 -m http.server 4291 --directory web/play
node Tools/smoke.mjs http://127.0.0.1:4291/
```

## The drawing system

1. A pointer press is ray-cast through the camera onto the world plane `z = 0`
   and clamped to the level's drawing bounds.
2. Points are distance-filtered while the finger moves, smoothed for the
   preview, and simplified with Ramer–Douglas–Peucker when the stroke ends.
3. `BeamBuilder` turns each segment into a rounded 3D capsule and an oriented
   box collider. The stroke is a real `StaticBody3D` — or an `AnimatableBody3D`
   for a bridge deck, whose sag moves the collision with it.
4. The pen budget is enforced during the drag: the stroke stops at the last
   centimetre rather than silently refusing to build.
5. The simulation only starts on Play. Undo and Reset are free before then.

The first release uses one clearly defined vertical drawing plane. That is a
design constraint, not a 2D trick: structures have depth, real colliders, mass
behaviour and real contact with the bee flight lane and the walker.

## How a level wins

| Mode | Win | Lose |
|---|---|---|
| Bee Defence | Keep Biscuit untouched for the timer | A bee reaches him |
| Bridge Build | Biscuit reaches the far lip | He falls, or the timer expires |
| Danger Dodge | Stay clear until the timer ends | A boulder, crate or ball touches him |
| Contraption | The ball rests on the pad | It leaves the toybox, or time runs out |

Stars are material efficiency: **3** at or under 66% of the pen, **2** at or
under 86%, otherwise **1**. The HUD shows the 3★ threshold before Play, and the
result card shows exactly what was spent. A legitimate completion always earns
at least one star.

## Verification

- `Levels.validate()` checks ids, modes, bounds, budgets, required data and that
  every stored solution fits its budget.
- `Scenes/Tests.tscn` builds each level, draws the stored stroke with the real
  `BeamBuilder`, starts the real simulation and requires `phase == won`.
- `Tools/smoke.mjs` boots the exported build, performs a real mouse drag on the
  canvas in a phone viewport, presses Play and waits for the win card, then
  checks the desktop layout. It also asserts the arcade bridge and client exist.

Measured on 2026-11-09: **20/20** stored solutions win in one headless run; a
real 5.43 m browser drag wins level 1 with three stars and no console errors;
58 fps in-level on a 390×844 phone viewport and 38–59 fps at 1280×800 after the
cold shader compile. The same smoke test passed against the deployed Pages URL.
The full report, including what was not tested, is in `docs/QA_REPORT.md`.

The live arcade entry is in `littlejoyarcade/src/data/games.ts` and migration
`0019_doodle_rescue_3d.sql`; the Supabase row (`sort_order` 16) and its 18
achievements were published and verified.

## Assets

All art is procedural: rounded primitives, shared materials, a gradient sky and
soft directional shadows. No textures or third-party models ship. Audio is
synthesised at 22.05 kHz mono, which keeps the payload small and avoids
licensing questions.

## Known limitations

- **20 levels, not 300.** The campaign is four complete worlds. The directive's
  300 levels were not generated or validated in this pass; every shipped level
  was replayed by the physics, and unvalidated levels were deliberately not
  included.
- **No rewarded ads.** No ad provider is configured and the game does not ask
  for one. `DoodleRescue.adsAllowed()` reports `false`; there is nothing to
  remove, so there is no ad-removal purchase either.
- **One drawing plane.** Depth-constrained and surface-constrained drawing are
  future work; bridge decks sag by a deterministic load model rather than
  soft-body deformation.
- **Bees use collision queries, not rigid bodies.** That is deliberate for
  browser performance; they steer, collide and bonk like physical insects.
- **Blender is not used.** The art is generated in GDScript instead, so there
  are no `.blend` sources to keep in sync.
- **Hardware coverage.** Tested in Chromium through Playwright at phone and
  desktop sizes. Safari iOS and Android Chrome use the same WebGL 2 path but
  were not exercised on physical devices here.
